# dsh-secretary —— 你的 DSH 助理

> 这是一个 **DSH 插件**，不是独立客户端：界面是 DSH 侧边栏里的一个面板，服务跑在 DSH 自己的 webServer 上，没有独立进程、不占端口。

一张便签画布 + 一个会定期汇报的助理：
**手写**你自己的工作（便签、勾完成、记进展）；
**自动**汇总 DSH 里各个工作区、各个线程在干什么（目标 / 进展 / 待办 / 消耗），每天定时生成一份简报放到画布上。

> 原定位是"便签看板"，现在以**助理**为主：便签画布是手写区，简报卡是自动区，两者互不覆盖。

DSH 的一个插件：侧边栏点开，整页就是一张画布，上面铺着便签。
每张便签是一个待办 —— 做完了点左上角的勾，卡片变淡划线归到「已完成」；
没做完就留着，或者给它补一条进展。顶部一直显示三个数：**共多少、没做完多少、已完成多少**。

## 助理简报（核心）

**一键生成**：顶栏「生成简报」——扫一遍所有工作区的会话，产出一张简报卡：

| 板块 | 内容 |
|---|---|
| 过去 N 小时 | 活跃任务数、推进中、已完成、需要你出手、消耗 |
| 需要你出手 | 在等你回答/审批、**近 2 天**内回合出错、**3–14 天**没再动的任务（更早的旧线程不打扰） |
| 在推进 | 目标、最近动作（跑命令/改代码/交付文件…）、待办进度、消耗、产出 |
| 已完成 | 目标 + 产出文件数 |
| token 用量 | 输入/输出/缓存 tokens，按工作区拆分 |

**每日自动**：默认**本机时间 08:00**，可在「设置」里改时间、保留天数、开关。到点且当天还没出过简报就生成；开机时若已过点会补一份。

**口径**：只统计 token 用量（未命中输入 / 命中输入 / 输出），不做费用估算。

**快照**：每天一份存在 `~/.dsh/workbench/briefs/YYYY-MM-DD.json`，默认保留 90 天（可改），过期自动清理。

**长期累计**：另一本账 `~/.dsh/workbench/cumulative.json`，**永不过期**。
按「会话 + 日期」整段记账（同一段历史重复读不会翻倍），累计 tokens、线程数、覆盖天数；
顶栏一直显示 `累计 1.45B tokens`，简报里有「长期累计」块。
前几次生成简报会把历史逐步补齐（每次最多补 20 个没记过账的线程）。

## 怎么用

| 操作 | 怎么做 |
|---|---|
| 新建便签 | 双击画布空白处，或点右下角 `＋` |
| 改内容 | 双击便签正文（新建后会自动进入编辑）；回车保存，Shift+回车换行 |
| 做完 | 点便签左上角复选框；再点一次取消 |
| 记一笔进展 | 便签底部「＋ 记进展」，回车保存 |
| 挪位置 | 按住卡片任意空白处拖动 |
| 删除 | 便签底部 `×`，或拖到右下角出现的垃圾桶 |
| 换颜色 | 鼠标移到便签上，底部出现六个色点 |
| 只看没做完 | 顶栏「只看没做完」，把勾掉的便签收起（仍然计数） |
| 自动排列 | 顶栏「自动排列」，按阅读顺序把所有便签铺成网格，一行放满 11 张就换行 |
| 拉取线程任务 | 顶栏「拉取线程任务」，扫描所有工作区的会话，把每个会话最后的待办清单拉成便签 |
| 生成简报 | 顶栏「生成简报」，产出一张助理简报卡（目标/进展/待办/消耗/需要你出手） |
| 设置 | 顶栏「设置」，改每日生成时间、快照保留天数、自动开关 |

顶部三个统计（共 / 没做完 / 已完成）就是「我到底还有多少活」的答案。

### 带上下文续做

点卡片上的「继续」时，会先生成一段草稿 **复制到剪贴板**，再打开对应会话：

```
接着上面的进度继续这个任务。

【目标】把工作台做成 DSH 助理
【还没做完】
- 加会话导入（进行中）
- 补测试
【最近进展】
- 日志读取改成直接解 zstd
【已有产出】
- /tmp/report.md
```

粘贴到输入框即可，**不会自动发送**。为什么要复制而不是直接放进输入框：这个 DSH 版本没有向 composer 投放草稿的客户端接口
（`layout / locale / sessions / slots / theme / uiWorkspace / workspaces` 里都没有，客户端事件也没有）。
剪贴板不可用时（比如无权限）会弹出文本框让你手动复制，功能不会丢。

### 长任务的进度

扫描/解析会话可能跑几百毫秒到几秒，期间画布上方会显示进度条：

```
◌ 解析会话日志        120/206       1.2s
[━━━━━━━━━━━━━━━━━━░░░░░░]
```

点下按钮立刻有反馈（先显示「准备中」），之后每 400ms 向宿主问一次 `/progress`。
完成后提示里会带上用时，例如「扫描 206 个会话 · 新增 13 张 · 用时 0.8s」。

排版（新建便签、导入、自动排列）走**一次批量请求** `POST /layout`，
不再「每张卡一个请求、每次整块读写真个看板」。

### 实时待验收

会话一轮跑完（`turn/end` 且 `reason.completed`）的瞬间，对应的卡片就会被标上「**待验收**」——
不等下一次扫描，也不改动你手改过的内容。面板每 15 秒自取一次看板，所以卡片是自己冒出来的：

- 卡片顶部出现绿色「● 待验收」，点一下即验收（等同勾完成）
- 顶栏出现「待验收 N」
- 拖拽/编辑期间不轮询，不打断你

## 界面风格

参考苹果备忘录：统一配色，不再有六色便签。

- 画布是浅色底，卡片是白色面板 + 发丝线 + 极轻投影，圆角 12px
- 只保留一个强调色（品牌色）用于勾选和新建；状态色（成功/警告/错误）只用来标"需要你出手 / 失败"
- 系统字体栈（SF Pro / PingFang SC），正文 13px / 19px 行高
- 顶栏 44px、细线分隔，像系统工具栏
- 简报卡同一套卡片语言，靠层次（分块标题 + 发丝线）区分，不用彩色描边

### 排布规则

- **新建的便签永远在最左**：新的落在左上角，其余便签依次右移；旧卡片位置会被重新计算
- 卡片**高度随内容长高**（进展、待办多了就变高），不做内部滚动条
- 装箱按**真实卡片高度**算：一行铺到画布右边距就换行，每行高度取该行最高的那张，高卡片不会压住下一行
- 画布高度跟着内容长，最后一行不会被截掉
- 「自动排列」按**阅读顺序**重排（上下差不多算同一行，行内从左往右）

## 从别的线程拉任务

顶栏「拉取线程任务」会扫一遍 DSH 里**所有工作区**的会话，把每个会话**最后一次** `todo_write`
的任务清单抽出来，变成一个会话一张卡：

- 卡片标题 = 会话标题，卡片里是它的待办清单（`✓ 完成` / `◐ 进行中` / `○ 未开始`）
- 底部标来源工作区；清单全部完成时，卡片直接是勾掉的状态
- **按会话去重**：重复点不会重复建卡
- **不覆盖你手改的**：你改过标题、勾过、记过进展的卡，再次拉取时会被跳过
- 子代理线程（subagent）不参与，跳过

数据来源（只读）：
- **直接解析会话日志** `~/.dsh/sessions/<project>/<session>/session.v4.jsonl.zstd`：
  多帧 zstd 逐帧解压、逐行容错；按 `size:mtime` 签名做**增量**，没变的会话复用上次摘要（缓存 `session-digests.json`）
- `~/.dsh/storages/workspace.json`：会话 → 工作区的归属
- `~/.dsh/storages/session_projcache/sessions/<id>.json`：DSH Session Goal（任务目标最权威的来源）

宿主只读，不会写 `~/.dsh/sessions`。

## 数据在哪

`~/.dsh/workbench/board.json`，明文 JSON，随时可以用编辑器看或备份。
写入是「临时文件 + rename」的原子写；JSON 写坏了会先备份成 `board.json.broken-<时间戳>`，不会默默清空。

## 安装

1. 打开 DSH → **插件 → 添加插件**
2. 填入仓库地址 `https://github.com/cozcc/dsh-secretary`（或本地 clone 的目录）
3. 启用后重启一次 DSH

左侧栏出现 **DSH 助理**，点开就是画布。

数据目录默认 `~/.dsh/secretary`，可在 `cordis.patch.yml` 的 `config.dataDir` 改（改完需要重启）。

## 开发

```bash
# 改完 src/*.mjs 后重新生成 lib/（浏览器端产物必须是 IIFE）
cd packages/workbench && node build-client.mjs

# 数据层测试
node --test test/board.test.mjs
```

- 改 `lib/client.js`（浏览器半边）后**刷新页面**即可；
- 改 `lib/index.js`（宿主半边，HTTP 路由 / 工具）需要**重启 DSH**；
- 改 `package.json` 的包名或 exports 必须重启。

### 结构

```
src/board.mjs    纯数据逻辑：便签增删改、勾选、进展、统计
src/store.mjs    落盘：原子写、并发串行、坏文件备份
src/http.mjs     同源 HTTP 路由 /workbench/api/*（owner 身份校验，令牌兜底）
src/logs.mjs     会话日志读取：多帧 zstd、逐行容错、签名增量 + 摘要缓存
src/index.mjs    Cordis 入口：挂路由 + 注册 workbench_* 工具
src/client.mjs   浏览器端画布（React.createElement 手写，无 JSX 编译）
```

浏览器端不碰文件系统，读写都走宿主挂的同源路由；写操作带
`X-Workbench-Token`（兜底）；首选是 DSH 的 owner 身份（`connection.admit`），不需要额外凭据。

## Agent 也能用

宿主注册了一组工具，可以直接让我帮你操作看板：

```
workbench_list            看看现在有多少活、哪些没做完
workbench_add_note        加一张便签
workbench_complete_note   勾完成 / 取消
workbench_add_progress    给某张便签补一条进展
workbench_update_note     改内容或颜色
workbench_delete_note     删掉
```
