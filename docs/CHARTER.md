## 1. 一句话定位

DSH 侧边栏里的个人秘书：便签画布 + 从每个会话的待办拉任务卡 + 定时简报/周报 + 永久 token 台账，回答"每个线程在做什么、还差什么、花了多少"。

## 2. 目标（每条都必须可验收）

- G1 便签画布可用 —— 验收：新建/勾完成/记进展/拖动/删除/导出 Markdown/变更历史，侧边栏操作一遍不报错。
- G2 线程任务卡 —— 验收：`拉取线程任务` 能跨工作区把每个会话最后一遍 `todo_write` 变成卡；未完成项可点击跳到该会话；同会话去重；用户改过的文本不被后续拉取覆盖。
- G3 简报与周报 —— 验收：`生成简报` 产出 24h 简报卡；默认 08:00 自动生成且启动时补跑当日缺失；本周看板给出会话数/消耗/完成数与环比。
- G4 累计台账 —— 验收：`cumulative.json` 按会话按天永久累计；重复读取同一会话是替换而非累加（幂等）；90 天后简报快照被清理而台账仍在。
- G5 验收徽章 —— 验收：某会话 `turn/end` 且 `completed` 后，其卡片立即出现「待验收」，点击即接受。

## 3. 不做（Non-goals）

- N1 不做独立应用/进程/端口 —— 原因：宿主内插件是它的存在方式，独立进程会带来鉴权与生命周期复杂度。
- N2 不改 DSH 宿主代码、不接管其他插件的面板 —— 原因：越界改动会在宿主升级时炸掉，且不属于本插件职责。
- N3 不做云同步 / 多设备 —— 原因：数据只服务本机本人，引入同步就要处理冲突与凭据，收益不成立。
- N4 不静默截断长文本 —— 原因：秘书的输入是人的记忆，宁可显式报错也不默默丢。
- N5 不做通用看板/项目管理（多用户、权限、甘特等）—— 原因：那是另一类产品，本项目只服务单个用户的本机会话。

## 4. 验收标准

- A1 `node --test test/*.test.mjs` 全绿（当前基线 44 passed）。
- A2 重启 DSH 后 `board.json` / `briefs/` / `cumulative.json` 数据仍在，且卡片顺序与完成态恢复。
- A3 超长便签文本返回显式错误，不出现被裁剪后的内容落盘。
- A4 `dataDir` 改到新目录并重启后，插件在新目录初始化成功，不报错。

## 5. 接口面（对外契约；破坏性变更必须改版）

| 类型 | 内容 | 兼容要求 |
|---|---|---|
| 工具 | `secretary_add_note` / `add_progress` / `update_note` / `complete_note` / `delete_note` / `list` / `import_sessions` / `daily_brief` | 名字与参数保持；删除/改名需改版并给迁移说明 |
| 配置键 | `dataDir`（空 = `~/.dsh/secretary`） | 删改语义需改版 |
| 客户端注入 | `@deepseek-ai/dsh-client-ui-layout`、`@deepseek-ai/dsh-client-ui-sidebar`，platform `web` | 宿主 slot 变更时同步适配 |
| 宿主服务 | `sessionQuery`（含 zstd 会话日志读取）、workspace 注册表、client slots | 依赖宿主能力，不私下读会话文件 |
| 数据文件 | `board.json`、`briefs/YYYY-MM-DD.json`、`cumulative.json`、`session-digests.json` | 格式不得静默破坏；旧数据必须能读或显式迁移 |
| 对外 HTTP | 插件自有路由（面板读写、导出、按日期取快照） | 路由语义变更需改版 |

## 6. 依赖与边界

- 依赖：DSH 宿主（sessionQuery / workspace / client-ui-layout / client-ui-sidebar）、本机 `~/.dsh/sessions` 会话日志。
- 边界：不碰 `~/.dsh` 下其他插件的数据；不读凭据文件；不自动发布或安装；跨插件问题只上报不代改。

## 7. 约束（安全 / 权限 / 数据 / 合规）

- C1 `dataDir` 内只写本插件自己的文件名，不写用户未指定的路径。
- C2 拉取会话卡时不得覆盖用户手改字段；系统字段（目标/产出）只做回填空缺。
- C3 简报快照可清理（默认 90 天，可配），`cumulative.json` 永久保留。
- C4 面板读写走 DSH 自有鉴权（owner 身份），不自行开端口鉴权。
